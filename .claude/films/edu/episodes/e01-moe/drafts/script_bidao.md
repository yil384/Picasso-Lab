## 0. 写在前面：两个必须先知道的事实问题

1. **我们自己的最佳论文里有一个算错的数。** arXiv 2510.05497v5 §I 写 "DeepSeek V3 have C_256^8 = 4,426,165,368
   combinations"。这个值其实是 C(64,8)。正确值是 **C(256,8) = 409,663,695,276,000（约 4.1×10¹⁴，约410万亿）**，
   我用 Python `math.comb` 算过。本剧本用正确值。上线前请告诉 Zhongkai，并考虑在 arXiv 上修正。片子里不拿这件事开玩笑
   （house rule：不开真人的玩笑）。
2. **“下一层还是同一个专家”是错的。** episodes.md 写的 "the same rooms chosen layer after layer" 不对：不同层的
   专家是不同的网络，编号相同也没有关系。论文 Ob1 讲的是“楼下进 i 号门，可以预告楼上进 j 号门”。真正“同一扇门”的是
   Ob2：同一层里相邻两个 token 常选同一个专家，高层更明显。VO 已按这个改。

## 1. 标题、logline、ONE idea、时长

| 项 | EN | ZH |
| --- | --- | --- |
| 片名 | **Bet You Can't Guess the Door** | **《256扇门的门道》**（全片唯一的双关：门 / 门道） |
| 副标题 | 671B parameters, 37B at a time | 6710亿参数，每次只用370亿 |
| X 帖首句 / 抖音标题 | DeepSeek has 256 experts per layer and calls 8 per token. Bet you can't guess which 8. | DeepSeek每层256个专家，每个token只挂8个号。挂哪8个？有门道。 |

**Logline。** 桌上摆着一座纸做的医院，DeepSeek 的每个 token 在每层楼要从 256 扇门里挑 8 扇进。大家通常把这些门想成
“科室”，我们查了，不是。退一步说它是“掷骰子”，我们又跟一只猫赌了一把，用 24,000+ 个真实请求的路由记录来对。结果是：
门背后有习惯，而习惯可以预测。这正是我们组 ISCA 2026 最佳论文的内容。

**ONE idea。** MoE 很大但稀疏：每个 token 只叫醒一小部分专家。路由**既不是按科室分诊，也不是掷骰子，而是有习惯**。
习惯可以提前预测，所以专家可以提前调度。大模型推理里最贵的往往不是算，是搬数据，省下来的时间就在这里。

**目标时长。** 125 s VO + 3.5 s 片尾 = 128.5 s（目标 110-130 s，硬上限 135 s）。

**隐喻：保留医院，但当成“错误直觉”来用。** 这样做不需要另找隐喻，理由有三：
- 中文观众天然懂“挂号 / 专家号 / 名医排长队”。英文观众也懂 specialist、appointment、fully booked，以及专科医生要等很久。
- 医院隐喻本身有一个缺陷：大家会默认“专家 = 科室”。这个缺陷正好就是本集要推翻的流行误解，所以 T1 的
  “错误直觉”一步不用额外找。
- 我们推翻的只是“门上挂科室牌”。分诊、排队、楼与楼之间坐摆渡车，这几个映射都是对的，后半段还能一直用。

## 7. 风险

**已避开的事实陷阱**
1. **论文 §I 的组合数错误。** 印的 4,426,165,368 是 C(64,8)。片中用 C(256,8) = 409,663,695,276,000。上线前请告知作者。
   如果作者愿意，可以单独做一条毕导式“公开更正”彩蛋，但必须作者点头，正片里不放。
2. **36B 与 37B。** L14 p.9 写 36B；用 DeepSeek-V3 报告摘要和 L07 p.32 的 37B。
3. **“下一层还是同一扇门”。** 不同层的专家不是同一个专家；层间讲的是“预告”，同一扇门只用于相邻 token（Ob2，高层）。
4. **“专家 = 科室”。** 我们推翻的是科室牌，不说“和学科无关”；Fig. 8b 里学科之间确实有差异，画面保留。
   “两扇不变”只针对 Llama 4 第 7 层，铭牌写明。
5. **“Hinton 1991 提出 MoE”。** 不使用（实际作者是 Jacobs、Jordan、Nowlan、Hinton）。
6. **6.6× 和 1.25× 都不上屏。**
   - 6.6× 来自对未来晶圆级 GPU 的模拟器结果（§V-A，自研模拟器，误差 <5%，用 8×H100 校准）。
   - 1.25× 只出现在摘要和贡献列表；§VI-C 正文写的是 Remap 15.5%、Dup 12.5%（Qwen3-235B，8×H100）。
   - 帖文如要提，必须带“模拟 / 未来晶圆级 GPU”限定，并先请作者核对 1.25× 的口径。
7. **60-90% 是建模值**（DeepSeek-V3，4K 序列，几种部署配置），VO 说“按我们的建模”，屏上有脚注。
8. **50% 的含义。** 它是在给定上一层 top-1 专家的条件下，“前 20% 候选覆盖的条件概率质量”，是在同一批数据上统计的。
   回放必须按这个定义复现，最好用一半 trace 学、另一半 trace 测。如果样本外的数低于 50%，屏上用我们自己测的数并标注，
   VO 改成 "almost half / 将近一半"。
9. **亮方块与 8 栋楼的对应**，需要对照 Fig. 9(a) 原图核实：方块是不是 8 块、每块 32 个专家。论文原话是
   "routed only to adjacent nodes"，DeepSeek 报告的说法是“最多 4 个节点”。如果对不上，就改立体书的楼数；
   还对不上，就把彩蛋换成“DeepSeek 自己每 10 分钟复制一次热门专家”（DS-V3 §3.4）。
10. **组合数没算节点限制。** B5 的 410 万亿是“完全随机”下的数，实际 DeepSeek 受节点限制，是 71,614,201,382,880。
    这一点由卡角脚注和 B9 兑现，没有藏起来。
11. **ISCA 2026 Best Paper 的来源是组内帖子文案。** 盖章前请对一下 ISCA 官方获奖页（我没有核到官方页面）。
12. **不碰政治。** 不提 H800 带宽的来历；中英文对比只谈语言，不谈其他。
13. **“DeepSeek 最难猜”是说可预测性，不是说质量。** 屏上写 "hardest to predict / 最难猜"，避免被读成拉踩。

**可能只在一种语言里成立的笑点**
- “专家号已满 / 挂不上专家号”在中文里是满分；英文的 appointment / fully booked 能懂，但力度弱一档。
  英文那一拍主要靠画面（长队、猫）撑。
- 《256扇门的门道》的“门道”双关只有中文成立，只放在标题，VO 不用。全片只有这一个谐音或双关。
- "Control group: one cat" / “对照组：一只猫”两边都成立，是全片最稳的笑点。
- “猫起步非常自信。猫什么都不知道。”两边都成立，但不能念成毕导的体育解说腔（creators §5.4 禁用他的口头禅）。
- 最后一句的“假正经道理”可能被个别观众读成在评论医疗资源（中文语境里“挂号难”有社会议题的影子）。
  语气要轻，对象是“排队”，不是医院；如果用户觉得有风险，备选是 “Chaos is just a pattern nobody logged yet.” /
  “乱，只是还没人记下来。”

**不确定、需要拍板的事**
1. **House rule “不在页面放模型名”。** 我理解它指的是制作工具的名字，本集讲的是 DeepSeek / Llama / Qwen / Kimi 这些研究对象本身。
   请用户确认（episodes.md 的 Q3 曾把它理解得更宽）。
2. **ZH VO 直接说“token”还是“词元”。** 我默认用 token，因为抖音观众被 API 计费教育过（未核实），下期再正式讲。

4. **Zhongkai 出镜但无台词**，需要他本人同意，并确认名牌写法、是否有中文名。
5. **B4 数据**：公开 trace 是否包含中文 MMLU 的 Llama 4 记录尚未核实。
6. **场景量偏大**（3 座纸医院、立体书、机房）。如果工期紧，先砍背景的两座小医院（B7 的三张小票改成直接从打印机出），
