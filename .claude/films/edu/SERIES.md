## 0 一页结论
1. **主线**《算力另计》/ Compute Not Included：CSE 291P "LLM System Optimization" 的 14 讲 + 组里的量子研究，做成 1:30-2:10 的竖屏
   讲解片（three.js + q5.js 逐帧，1080x1920，30 fps）。X 英文版，抖音中文版；画面渲一次，字幕和画中文字按语言分开。
2. **外观**沿用已批准的 launch film 书房（"可以可以，就要这个质感"）；讲解都是台灯下**桌上的实体微缩模型**；"机器内部"切到真 3D 硬件。
3. **角色**：戴红色画家帽的白猫是沉默的观众替身；丁老师每集至多一句，须本人审定；成员客串；红色噪声小怪兽当反派。
4. **声音**：成员真人旁白，"我们"口吻，冷面，让数字制造兴奋；中英文各自原生写稿；静音也必须看得懂。
5. **数字**：每个都有出处（讲次 + 页码、论文章节或自测脚本）。不编数字、标题、引语。
6. **第一季 10 集**：pilot = L14-A "671B parameters, 37B at a time"（MoE，结尾转到 ISCA'26 Best Paper）；备选 L01-A "7 characters, 1 token"。
7. **支线**《这题不考》/ Not on the Exam：iPhone 实拍的"伪讲座"。笑点和剪辑取舍归人，字幕、图形、混音、交付归代码。
8. **头号风险是品味**（"HTML味 / AI味"、幻灯片感），不是技术：先定 4 张 9:16 style frame，再做动画。第二风险是磁盘（只剩 17 GB）。

## 1 定位与受众
**一句话**：一个实验室，把自己讲的课和自己做的研究，摆成书桌上的微缩模型，讲给一只猫听。

三条底线（用户历次反馈，identity §2）：
- **先教东西，研究是转折，不是奖杯。** launch film v2 的反馈原话："我要的是介绍Picassolab的首支post，不是介绍best paper"。
  每集的主角是一个概念；组里的论文只在结尾做 10-15 s 的反转。
- **像一个 Lab 做的东西**（v3："做的不像是一个Lab的东西，和学术毫无关系啊"）：真课程、真论文、真测量上屏。
- **独特、惊艳、新奇、幽默同时具备**；"很平庸"就是失败。

## 2 系列与命名
### 2.1 结构
- **主线按季**。每集是 THE BILL（launch film 打出的小票）上的一行：`No.07  KV CACHE ........ see receipt` / `第07项  KV缓存 …… 另计`；
  季终打印 TOTAL。小票原有的行（GPU TIME / MEMORY + CHIPS / DATA MOVEMENT / THE NEXT COMPUTER (TBD)）正对应 LLM 系统、硬件、量子。
- **支线按迷你系列**，多日挑战拆 3-4 集。抖音每季 / 每个迷你系列一个合集。
- **伞品牌**：X 维持 @PicassoLabUCSD；抖音显示名可用 "Picasso Lab｜毕加索实验室"，repo 里没有实验室中文名 [#3]。

## 4 声音
| 选项 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |

| B 丁老师本人 | 权威最高 | 她的时间；自嘲喜剧放在 PI 身上别扭；课堂录音音质 (unverified)、即兴、可能录到学生 | 只给**每集至多一句** |

| D 无旁白，纯画面文字 | launch film 已验证；静音友好 | 阅读速度限制深度（v9 110 s 约 331 词）；抖音科普靠声音 | 只做 15-30 s 预告 |

**推荐 A + 丁老师一句**；猫不出声；画面和烧录字幕在静音下独立讲完故事（`social/x/kit.html` 已写明：X 静音自动播放，画面大字要自己讲清故事）。

**旁白规则**
- "我们 / we"（实验室作主语）；描述观众经历用"你"。冷面，不用夸张形容词。EN、ZH **各自原生写稿**；双关是替换，不是翻译。
- 每 15-25 s 一个问题做章节转折（"那这时候你肯定要问……" / "So why not just…?"）；每集一个假结局（"对吧？不对。" / "Done, right?
  Not quite."）；每集一个诚实限定：这个数字**不能**说明什么。
- 结尾一句能被引用的话，回扣开头。英文版不做"点赞关注"；抖音版可加一句原生 CTA。系列自有 running gag 候选："这一步，Yufei 老师
  上课讲过"（须她同意）。

**录音**：安静、干声的房间（混响去不掉）；领夹麦、USB 麦或 DJI Mic 3；后期链 `highpass=f=80`、轻 `afftdn`、`deesser`、`acompressor`、
轻 `alimiter`。样片阶段用 macOS `say`（中英都有）做临时旁白，**临时旁白永不发布**。

**须用户决定**：谁录 EN、谁录 ZH [#4]；哪种语言的录音做时间轴主轨 [#5]；丁老师那一句和课堂录音 [#6]。原需求写抖音版是"中文字幕版"，
本草案按 house decision 做中文原生旁白；找不到中文配音时，退路是英文旁白 + 中文字幕，中文独有的笑点放进字幕旁注（"译者注"式吐槽）。

### 5.2 讲解 = 桌上的实体微缩模型
隐喻全部做成台灯下、桌面尺度的实物：纸 / 卡纸建筑模型、亚克力或麻将式 token 牌、纸条、硬币。浅景深，像 tilt-shift 微缩摄影；
俯拍或 45°。红笔、印章、便利贴在模型旁批注。图表变成物体堆（launch film 的年份图就是一摞论文）。数字用滚动计数器，配一个人类单位。

| 集 | 桌上的微缩模型 |
| --- | --- |
| 1 MoE | 卡纸医院中庭，256 扇诊室门；token 是取号的病人；楼与楼之间的接驳车 |
| 2 Tokenization | 活字印刷：铅字块在排字盘上熔合（用真活字照片 / 扫描纹理） |
| 3 KV cache | 书架：每个新 token 往每层书架加一对书，堆成塔；GQA、MLA 让塔两次塌缩 |
| 4 投机解码 | 半透明草稿牌冲在前面，红章一次盖完一排 ACCEPT / REJECT；草稿长成树 |
| 5 PagedAttention | 纸做的食堂座位或立体停车场；保温杯占座；块表是夹板上的票据 |
| 6 量化 | 硬币落到刻度尺上；弹珠从斜坡落到台阶；1% 的关键权重戴金头盔 |
| 7 训练规模 | 黑板算式里的因子逐个落下（打孔卡、河流），再拉远进真 3D 机房 |
| 8 流水线并行 | 纸做的饺子流水线（擀皮→包馅→捏边→下锅），下方纸条画出 Gantt；DualPipe 两条反向传送带像拉链咬合 |
| 9 SABRE | 高铁车厢座位图，乘客换座 |
| 10 Qubrio | 网格上的珠子原子阵列，整排平移；Qubrio 原片只在桌上的手机或打印漫画页里出现 |

### 5.3 "机器内部"、实拍插入、镜头
- 硬件一律真 3D，用书房同一套布光：`gear.js` 的 GPU 卡和机房（v10 推过迷你机柜玻璃门进机房）、规划中的 GPU 封装（die、SM 网格、
  HBM、可掀顶盖）、丁老师短片里的 3D 量子芯片。可插 2-3 s iPhone 实拍组里真实的服务器和线缆（相当于 Tim 的器材镜头）。
- 项目漫画片（Qubrio、TritonGym、TritonDFT、ChipMATE）只作画中物：桌上的手机在播，或打印的漫画页，镜头推进去。两种画风绝不同框。
- 镜头：每个镜头一条有动机的 `camPath`，不走走停停；剪辑落在 2 s 节拍上；不抖；大转场用半调网点擦除或有物理原因的 match cut
  （何同学式丝滑）；甩镜头不用叠化；不卡顿、不闪烁突变。A/B 对比在竖屏里上下分，撕纸缝。

禁止：UI 面板、仪表盘、默认图表、居中加字距的标题、边框、通用辉光、默认光滑材质、程序生成的假纹理、纯色平铺背景、字幕后的深色
底框（用边缘压暗）、逐字跳动的字幕、代码几何体画角色或道具、写实与手绘同框、贴纸感角色、凭空出现或穿模、版权梗图、emoji、罐头笑声。

动画；每个 primitive 在 gallery 里单独过一遍。

## 6 每集结构
### 6.1 开场钩子（0-3 s 放主张，3-15 s 放代价）
| # | 公式 | ZH 例 | EN 例 |
| --- | --- | --- | --- |
| 1 | 数字悖论（Tim / 何同学） | 这块GPU显存满了，其中一半是空的。 | This GPU is full. Half of it is empty. |
| 2 | 打赌（毕导） | 打个赌：一个小模型能让大模型变快，而且一个字都不改。 | Bet a small model can't speed up a big one without changing a word. |
| 3 | A/B 对照（何同学） | 左边每次只出一个字，右边一次猜五个。最后一模一样。 | Left: one token at a time. Right: guesses five. Same output. |
| 4 | 共同烦恼 + 认可（Tim） | 你一定见过：AI 回答时第一个字总要卡一下。不是你的错觉。 | Ever notice the first word takes the longest? You're not imagining it. |
| 5 | 投票（毕导，改造） | A 还是 B？先在评论区站队。 | A or B? Reply before you watch.（帖文挂 X 投票） |

另有"教科书错了"（毕导），只在我们自己的数据支持时用。规则：第一帧是构图完整的封面（≤ 8 个汉字或 ≤ 5 个英文词）；第一句口播
≤ 2.5 s；主张之前不放 logo、不自我介绍；例句里的数字发布前再核出处。

### 6.2 模板（按 90 s 写；主线 1:30-2:10 按比例放大）
- **T1 错误直觉（毕导 loop，主线默认）**：0-3 主张或打赌（封面帧）→ 3-12 一个具体场景（一个请求、一张卡）→ 12-25 把流行直觉讲得
  很像真的 → 25-28 投票 /"我们直接试一下"→ 28-55 实验：真测量或真模拟，做成带计时的比赛 → 55-70 揭晓，一张图讲清机制，至多一个
  公式 → 70-82 没人问的额外漂亮事实 → 82-90 回扣 + 冷面"人生道理" + tag。
- **T2 管线延迟（Tim《音画不同步》，serving / latency 选题）**：抱怨 →"不是你的错觉"→ 现实基线 → 人类阈值（ms）→ 逐级走管线
  （tokenize → prefill → decode → stream）→"对吧？不对"→ 工程师的妙招 → 妙招在哪失效 → 一句反思。
- **T3 对比 → 升级 → 机制（何同学打字机，pilot 用）**：A/B 冷开场 →"不是……不是……而是……"的数字升级 → 小悲剧或反转 → 在可动
  模型上演示机制 → 连回现在 → 引语或人的尾声。
- **T4 预注册实验（何同学快充，用自测破除迷思）**：民间说法 → 屏幕上列协议（组别、对照）→ 数据前先说"如果 X，就说明 Y"→ 带小数的
  结果 → 结论的边界 → 实用结论。
- **T5 带失败的探险（何同学 AirDesk / 5G，主要给支线）**：个人动机 → 天真方案 + 代价 → v1 好笑地失败（"工作得很完美，除了……"）→
  v2 → 兑现 → 预判观众问题，先给假答案再收回 → 人的尾声。

主线时间图（platforms §4）：0-3 钩子 → 3-20 问题与代价 → 20-100 机制（微缩模型场景）→ 100-125 兑现 + 一个喜剧收尾 → 125-135
下一集预告。关键数字那一拍是**安静区**：不压笑话，tag 晚一拍。每集最后 5 s 埋下一集（ep2 结尾"每个 token 都会留下一段记忆……"→ ep3）。

### 6.3 片头片尾
- **冷开场在前**：前 3-6 s 是钩子（问题本身，或猫闯的祸）；第 0 帧是构图完整的静物，也是 X 缩略图。**标题 stinger ≤ 1.5 s**：台灯
  开关"咔哒"点亮桌面 → 打印机吐出一行小票即本集标题 → 红笔打钩（标题区，轨道色）。
- **片尾 ≤ 4 s**：猫给这一行盖章（FASTER / CHEAPER / IN PROGRESS，或 EXPLAINED / 讲完了）→ 小票再滚出下一集一行 → 脚注 + 账号 +
  真 3D logo。最后一帧能无缝接回第 0 帧（X 会循环）。
- **声音 logo**：iPhone 录一次的三个真拟音：台灯咔哒、打印机走纸、盖章闷响；可选一声真猫叫。不做合成 jingle。
- **旁白密度**：约 3.5-4.5 字/s、2.3-2.8 英文词/s（通用基准 (unverified)）；1:30-2:10 约 230-340 个英文词（按 150-160 wpm）或
  320-580 字（推算）；不能快过字幕可读速度（§8.3）。

### 6.4 发布检查表
**打分项**（每项 0-2，满 18，≥ 14 才发）：1 第一帧能当封面，主张 3 s 内落地；2 前 30 s 内出现真东西（测量、trace、硬件镜头）；
3 错误直觉讲得公平；4 屏幕上跑一次带计时的实验或比赛；5 每个数字有人类单位和 source tag；6 至多一个公式，不懂也不影响理解；
7 一个结构性笑点（反高潮、假答案、meta），单独截出来也成立；8 说了一个诚实限定；9 最后一句可引用并回扣开头，中英各自原生。
**硬门槛**（缺一不发）：剧本每个数字有 `SRC:`；每个笑点过了 §7.2 四项测试；丁老师那句已获确认，否则删掉；安全区检查帧通过；
手机上静音看完一遍；中文字幕由母语者读过；抖音勾选 AI 标注；两个平台的音乐授权清楚。

## 7 喜剧规则
### 7.1 手法
- **基础：铺垫 + 包袱，预期违背。** 讲解片里最自然的铺垫就是观众的天真直觉；先摆误解再拆，比平铺直叙更有效（Muller 2008）。
- **装傻 / 吐槽（manzai）是系列核心手法**：装傻说出科普迷思或天真设计，吐槽用真实机制纠正，纠正本身就是包袱，准确性内建在笑话里。
  默认分工：旁白先把流行直觉讲得像真的，再亲口推翻；猫的便利贴 = 观众的"傻问题"；红笔 = 吐槽与批注（≤ 6 个英文词或 ≤ 10 个
  汉字，配一个小音效）。
- **三翻四抖**：同方向铺垫两三次，最后一拍反转。系统题目自带：10 → 1,000 → 100,000，GPU 着火。节奏、景别、字的位置、音效保持
  一致，反转落在剪辑点上。每集 1-2 次。
- **场景错位**（《互联网体检》式）：前提就是带规则的类比。写剧本前先写**映射表**（前提元素 → 系统元素）；观众能从规则猜到下一个
  笑点时就懂了。每集一个前提，5 s 内读懂；类比失效处是免费的吐槽点。
- **Callback 与 running gag**：前 15-20 s 埋一个**看得见的**东西，最后 10-15 s 兑现，兑现时带出结论。running gag 出现三次（埋、
  升级、反转），最好是机制里本来就重复的东西（每个 decode step、每个 micro-batch）。
- **反差**：给极小的东西（一个 INT4 数、一个 token）办一场史诗发布会，但先正经演一次。**Act-out**：物体演出机制，代码保证位置和
  时序就是真算法。**自嘲**只朝我们自己（GPU 预算、台灯、渲了多少帧），不说"量子谁也不懂"这类反科学的话。
- **参照创作者的结构梗**：努力后的反高潮（"研究了三个月后，我们放弃了"）；假答案再收回（"对不起，刚才是我编的"）；很巧 / 更巧 /
  最巧；拟人 + 体育解说；meta（"这条视频也是边生成边播放的"）；冷面人生道理；片尾彩蛋。**真诚转折**：最后一拍说一句为什么这个
  问题重要（像 Paper #137 和那把空椅子），然后才是脚注。

### 7.2 每个笑点拍摄前过四项测试
1. **Resolution**：只有懂了机制才笑得出来，才算教学笑点。不懂也能笑的是装饰，只许出现在冷开场；讲完还看不懂的，删。
2. **Truth**：旁白开玩笑时画面依然技术正确（注意力矩阵形状对、因果 mask 是下三角、屏幕上的数字是真的）。
3. **Number**：笑话里的数字要么真实有出处，要么荒诞到没人当真（"十亿年"）；绝不用看似合理的编造数（"快了 37%"）。
4. **Analogy-break**：每个类比都会在某处失效，把那处说出来，当一个吐槽拍。

流程：每集一个 `JOKES_epNN.md`，笑点里的每个事实有出处，懂行的成员审一遍。准确性否决权大于笑声。

### 7.3 密度与位置（建议值，非实测规律）
| 时长 | 笑点数 | 组成 |
| --- | --- | --- |
| 60 s | 4-6 | 一个前提、一次吐槽纠正、一个 tag |
| 90 s | 6-9 | 再加一个由机制驱动的三翻四抖 |
| 150 s | 9-13 | 再加一个 running gag（3 次）和一个 callback |

位置：0-3 s 笑点就是问题本身；3-15 s 立前提；中段机制 + 三翻四抖 + 一次装傻吐槽；关键数字处安静；最后带结论的 callback、一句
名场面、一句真诚话、脚注。**两层笑点**：大众看情境（酒店、回转寿司），工程师看角落细节（房号正好是 block size）。

### 7.4 双语分级
| 级 | 跨语言 | 例 | 规则 |
| --- | --- | --- | --- |
| A 通用 | 能 | act-out、场景错位、视觉反差、画面化的三翻四抖、对画中物的 callback、猫的肢体喜剧 | 约 70% 的笑点放这里，画面锁定 |
| B 重写 | 换一句 | 语言上的预期违背、自嘲、成语改写、文化梗 | 同一时间点，两句独立写的包袱 |
| C 单语 | 不能 | 谐音梗、中文网络梗、英文双关（cache / cash） | 另一语言同一拍放别的笑点或正经讲；永不解释双关，只替换 |

锁画面锁的是包袱的时间点，不是词：每个口头包袱后留 0.5-1.0 s 余量。谐音梗只限中文，每集至多一个，且不能是那一拍唯一的笑点
（"谐音梗要扣钱"仍是观众默认反应）。文化替换：春运 / holiday airport rush；摸鱼 / scheduled slacking；传纸条 / passing notes；
交卷 / pencils down；斗地主 / poker；小组作业 / group project；食堂打饭 / DMV line。

### 7.5 不做
- **向下打**：学生、"这都不懂"、口音、地域、性别、外貌、残障、宗教（科学课堂调查：关于科学的笑话 89.3% 觉得好笑、1.5% 觉得冒犯，
  冒犯集中在身份类笑话，Cooper et al. 2018）。**尖刻讽刺**：实验显示它降低信息和科学家的可信度；温和调侃问题本身可以。
- **政治与地缘**：芯片出口管制（L14 上 H800 的 NVLink 只讲带宽，不讲原因）、中美 AI 竞赛、军队、选举、AI 末日之争（2023 年笑果
  运营公司因一个涉军笑话被罚 13,353,816 元）。
- **抄梗**（借手法不借台词）、**炒作梗**（"AGI 下周二到"）、过气梗（草莓数 r、"X is all you need"）、黑话（yyds、绝绝子、遥遥领先）。
- **"AI味"笑话**：模板笑话、没有情境的术语双关、解释笑话、罐头笑声、梗图贴纸、和机制无关的笑点堆。解药是具体：真数字、真细节、真约束。

笑话库：comedy.md §5 有 48 条（tokenization、attention、KV、量化、MoE、并行、投机解码、编译、RL、量子、账号级），每条带出处和注意事项。

## 9 主线制作流程（edu-kit）
### 9.1 原则
- **不造新引擎**：fork video-kit 的 pv（`runtime/pv.js` + `render.py` + `pvlib.py`，launch film 已在上面跑过 2000+ 帧），加时间轴、
  字幕层、音频阶段、primitive 库。**一张画面，多份交付**：picture pass 渲一次，每种语言一个透明 overlay pass，编码时合成。
- **时间按旁白写，不按绝对帧写**：模块只读 beat 上下文 `B`（`B.at('half')`、`B.after(anchor, dur)`、`B.u`……），重录旁白后画面自动
  重新对时；每帧、每个采样都是（剧集文件，帧号）的纯函数。住在 repo 里原地运行；大媒体放 `~/PicassoEdu/`，用 sha256 引用。
- Python 守项目约定：每个 helper 返回 `(value, None)` 或 `(None, "error")`；目标 `/usr/bin/python3` 3.9（无 `match`、无 `X | Y`）。

### 9.2 流程
1. **`script.md`**（唯一手写源）：按 beat 写 EN、ZH 旁白、`[[anchor]]`、`(pause 0.4)`、`SFX:`、`MUSIC:`；**任何数字都要有 `SRC:`**。
2. **临时旁白 + 动画样片**：`say` 生成临时旁白，每个 beat 先用占位卡（beat id、文案、计划模块、anchor 刻度），第一天就能审故事和节奏。
3. **真旁白 → 清理 → 对齐**：Whisper（已缓存 `small.en`）转写后和剧本 diff，列出即兴、漏词、重录；CTC 强制对齐（torchaudio
   `forced_align` + 已缓存 `WAV2VEC2_ASR_BASE_960H`）给词级时间，停顿处比 Whisper 准得多，而停顿就是喜剧节奏。数字先规范成口语。
   中文要下载 `MMS_FA`（uroman）或多语 Whisper。低分词（< 0.5）标出。torchaudio 锁 2.8。
4. **`beats.json`**（生成并提交，音画契约）：帧区间、anchor、中英字幕 cue、SFX、音乐事件，记录上游 sha256，`edu status` 报过期。
5. **场景模块**共用一个 stage；转场在剧本里声明（cut / whip / match / push / dotwipe）；`edu cues` 空跑收集音效 → `cues.json`。
6. **Picture pass**（Mac Metal，渲一次）→ 近无损中间片分段；**overlay pass** 每语言一次，透明 RGBA PNG，相同帧去重（约 34 KB/帧）。
7. **双语与"画面只渲一次"**：一条 beat 时间轴，由主轨语言的旁白生成 [#5]；另一语言按画面配录，靠包袱后 0.5-1.0 s 的余量装进
   同一 beat；装不下就改词，不改画面；两种语言各自对齐，只驱动字幕和混音。画中文字：便利贴字、红笔批注、小票行、章字、章节牌在
   overlay pass 里按语言画；**必须印在 3D 物体上随镜头运动**的少数文字（如打印机吐小票特写），对该镜头范围按语言各渲一次 picture
   （`--range`）；其余 3D 内文字保持语言中性（数字、"KV cache""HBM" 这类术语）。
8. **混音 `mix.py`**：按对齐出的语音段压低音乐（段内 -10 dB，120 ms 起、350 ms 放），脚本里的停顿保持安静；SFX 来自 `cues.json`；
   两遍 `loudnorm` 到 -14 LUFS；导出分轨和无音乐版。**编码 `encode.py`**：`overlay=format=gbrp` 在 RGB 下合成再转 bt709 yuv420p。
9. **评审**：`preview.html`（手机尺寸、跟音频时钟、安全区遮罩、EN/ZH 切换）、逐拍 contact sheet、540x960 样片。四个视角至少三轮：
   创意总监、风格化 3D 技术美术、**对照幻灯片的领域专家**、X / 抖音平台编辑。

**Primitive 库**（都是书房里的实物，各有 gallery 静帧；屏幕数字来自 `beats.json` + `SRC`，不写死在代码里）：TokenTiles · Tensor ·
GpuPackage（真 3D）· MemoryTower（抽屉 → 书架 → 仓库 → 另一座城）· Queue（票据、托盘、纸条 Gantt）· Blocks（座位 + 夹板块表）·
CodeCard（印在纸卡上，荧光笔 + 红圈，不是 UI 窗口）· Odometer · Split · 拟声字 · ChapterCard · Cast（摆姿势，不做口型）· 喜剧工具
（定格 + 红笔标签、急推、猫的白眼插入、盖章 NOPE、callback、一本正经的荒诞计算）。

### 9.3 本机（2026-10-04 实测）与磁盘
- Apple M2，16 GB，**磁盘只剩 17 GB（92%）**。1080x1920 NPR demo 在 Metal 下 **0.10-0.14 s/帧/浏览器**（约 80 ms 是 PNG 编码）；
  书房场景（Reflector、bokeh、bloom）更重，未测，第 1 步先测。云端 SwiftShader 慢 10-30 倍，只写场景和 540x960 截帧。负载 > 约 12
  时降到 1 个 worker（其他 agent 的 Chromium 抢 GPU）。
- 中间格式实测（每帧 / 150 s 一集）：PNG 4.8 MB / 21.6 GB；`libx264rgb -qp 0`（pv 默认）3.66 MB / 16.5 GB；ProRes 422 HQ 0.96 MB /
  4.3 GB；**`libx264 -crf 8 yuv444p` 0.61 MB / 2.7 GB（采用）**。
- **渲染里不加逐帧颗粒**（静态纸纹即可，颗粒在终编码时用固定种子加），这是体积爆炸的主因；编码后删分段；`EDU_OUT` 可指向外置盘
  [#18]；`edu doctor` 空间不够就拒绝终渲。

### 9.4 要补的缺口
- PATH 上的 ffmpeg 没有 libass、drawtext、zscale：用 `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`。q5 只在 `anime/tiga/vendor/`，
  要加 q5 图层；`type.js` 写死 1080x1350，要参数化。
- 没有 vendor 任何 OFL 中文字体：`fonts.py` 用 fontTools 每集子集化（woff2 需 `pip install brotli`）；加载检查带样字，渲染后逐条 cue 查豆腐块。
- pvlib 的场景哈希不追踪绝对路径 `/scene/...` 的 import，可能续渲到过期帧：改为哈希页面实际加载的全部文件；加每帧超时。

### 9.5 目录、续作、搭建计划
- `.claude/films/edu/`：`README.md`（续作简报）、`SERIES.md`、`kit/`（`edu` CLI、runtime、prims、fonts、sfx、gallery、preview）、

  一块"请试试 117 诊室"的小牌）→ 跨楼接驳（专家并行的 all-to-all，接驳车堵车）。
- **反转（约 15 s）**：俯拍接驳车流的延时，看似随机的车灯变成高速路（同一批诊室层层被选、总成对出现的诊室、共激活热图里的方块），
  切到论文标题和 Best Paper 奖章：预测流量，高峰前先搬专家。launch film v2 那段 16 s"放大镜侦探"漫画可作为桌上的打印漫画页复用。
- **喜剧**："专家号永远挂不上"；猫溜进没人去的诊室睡觉；收尾卡 "Only 5.5% of the brain works per word. Same as me on Monday."
  （37/671 ≈ 5.5%）。客串 Zhongkai Yu [#11]。**风险**：一集两个想法，规律只做 15 s 反转（用户强调过"不是介绍 best paper"）。
- **备选 L01-A**：制作风险最低（只有活字块，不需要角色），事实全部用 tiktoken 本地验证（"中华人民共和国" cl100k 7 个 token、o200k
  1 个），题目最普适；缺点是没有研究连接，作为实验室的第一句话偏弱。

### 11.3 用前需复核的数字
课件与外部来源或自测之间有几处出入；用到时以括号里的为准：
- DeepSeek-V3 激活参数：L07 p.32 写 37B，L14 p.9 写 36B（以 DeepSeek 技术报告摘要的 **37B** 为准）。
- 6.6× 平均加速是 **wafer-scale** 硬件上的（模拟还是实测，查论文原文措辞）；今天的 GPU 上至多 1.25×。不带限定词不说"快 6.6 倍"。
- L01 p.22 "1000" 算一个 token（cl100k、o200k 实测都是 ['100','0']）；旧 L01 highlight 视频的目标词表 11（现行 p.17 的 13 正确）。
- L06 p.3 权重项（按 130.4 GB 算，ZeRO-2 / ZeRO-3 每卡 187.4 / 65.2 GB；单位 GiB；不含激活）。
- L03 p.12 405B 模型 1M token 的 KV（按公式约 7.5 TiB）；L04 p.13 16K 卡的天数（算出 13.0-13.3 天，说"大约两周"；"54 天"是课堂估算）。
- L08 pp.10, 17 的 Medusa / EAGLE 引用（第一作者 Tianle Cai、Yuhui Li，上屏前核实）；L14 p.6 的 1991 年 MoE 论文（Jacobs, Jordan,
  Nowlan & Hinton）；L02 p.20 列出的闭源模型激活函数（架构未公开，不复述）。
- ep4 标题里的 "3×" 需要具体出处，否则说"每步几个 token"；"输出一样"指同一**分布**，greedy 下才逐字相同。
- ep9 "91% fewer additional gates" 来自摘要的搜索摘要，查原文；今天的 Qiskit Sabre 含 LightSABRE 修改，措辞用 "probably"、"builds on"。
- ep10 网站上有两个不同的 "30.3"（每次 AOD 移动 30.3 vs 1.7 个原子；对 Enola 的 30.3× 加速），只用一个并标清；LLM 底座名字不上屏
  （house rule：页面里不放模型名；作为题材的模型名如 DeepSeek-V3、GPT-4o 分词器是否例外 [#23]）。
- 厂商数字（Colossus 卡数、Rubin 规格、NVFP4、上下文长度）在画面上标 "per vendor"；邀请讲座（L09-L11）署名讲者，L10 带讲者的
  "个人观点"声明。
